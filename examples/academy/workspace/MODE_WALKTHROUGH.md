# Short practice for the three modes

The supplied-project workspace adds one short task above its existing calculator controls.
Plan, exact rejection, revised Approval and fresh Auto use those same controls and tools.
The optional Guided tutor answers short questions about the current step. No model inference, alternate file
store, automatic write or click-based completion is introduced.

The tutor is explicitly labelled authored guidance with no AI inference. Ask Next (also Help,
Hint or What should I do), Why, Files or Customize. Next/Why use the current task, including
its revised title/presets. Files names only actual pending proposal paths and explains that
bases are checked when applying; no proposal means no invented files. Customize explains the
supported title/preset requests. Questions are limited to 200 characters; unknown questions
receive an honest limitation. Asking never calls tools, writes, approves or advances practice.
Answers clear on controller updates so an old response is not presented as current. Busy
operations request a wait; rejected or consumed proposals (including refused stale applies) provide no pending file list.
This is optional contextual help, not general reasoning, a connected agent or saved chat.

CalculatorModes publishes frozen operation receipts only after an actual proposal, rejection
or fully acknowledged apply with a passing real project check. Auto clears its intermediate
plan receipt before applying; failed/partial/stale writes and failed/malformed checks provide
no successful apply receipt. Mode selection does not create a receipt. The guide follows
receipt kinds, original proposal identity and authored request intent, not status prose.

The rejected proposal must be the one inspected in Plan. The first Plan may add the calculator or rename an existing one. Revised Approval must use
the same action with a different title; its suggestion also differs from the actual source.
Auto must apply genuinely different ordered preset values. Equivalent title escapes or preset
spacing do not create proposals or advance practice. Replaying the same receipt cannot satisfy a differently typed next
step. Unsupported requests and actual diagnostics remain in the editing controls. Out-of-order
writes retain source and explain that this practice step was not followed; no reset overwrites
learner work. Reloading starts fresh practice on the current calculator without resetting its source.
The guide chooses a changed title and presets from the actual reviewed source. It never
infers historical completion from files. General curriculum recovery remains open.

This is session-only mode practice, not persisted curriculum progress or certificate evidence.
Its final text records the three modes used and asks the learner to build and try the actual
calculator, including the separate saved-output verification action. It does not assert that a later edit is checked or that a frame load proves behavior.
