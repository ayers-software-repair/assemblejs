## Verdict

The security core holds. `encodeIslandJson` could not be defeated by any input tried, including
`</script` in a key, a lone surrogate, a real own `__proto__` key, and both line separators;
`escapeAttribute` cannot end a quoted attribute; and every one of the eight protections the two
commit messages claim to have watched failing does in fact go red when reverted and green when
restored. Section 4 found no false claim.

Three of the commits' own stated claims are nonetheless false or overstated. The headline one is
that `pnpm check` "could not pass on a clean clone" and now can: it still cannot, reproducibly,
though for a different reason than the one fixed. The composer's central promise - the page
"never fails because one of them did" - is defeated by four one-line transports. And `maxBytes`
is a declared safety limit with no enforcement anywhere.

The most likely-to-bite defect is not in the encoders. It is `cacheKey`, where an unescaped
separator lets two different assemblies share one cache entry.

## What is genuinely solid

- **`encodeIslandJson` cannot be defeated.** It escapes the whole `JSON.stringify` output, so keys
  are covered as well as values. `</script` in a key, `</script` nested three objects deep, an
  already-entity-escaped `&lt;/script&gt;`, a lone surrogate (`\ud800`, well-formed per ES2019), 60
  levels of nesting, a real own `__proto__` key, and both line separators all came back with no
  raw `<`, `>`, `&`, U+2028 or U+2029, and `JSON.parse(output)` deep-equalled the input every time.
  `JSON.parse` gives `__proto__` as an own data property; `Object.prototype` was not polluted.
- **`escapeAttribute` holds.** Backtick, newline, tab and NUL pass through unescaped and are all
  inert inside a quoted attribute; `render-envelope.ts:28,32` always double-quotes, so the
  unquoted-attribute risk has no caller. Double-encoding is correct: `&quot;` -> `&amp;quot;`,
  already asserted at `escape-attribute.test.ts:19`.
- **The projection stops what it claims to stop at the top level.** A source grown with `headers`
  did not cross. Six names, no spread.
- **The timeout timer is always cleared.** A fast fetch with a 30s deadline composes in 1ms and the
  process exits in 2ms with `process.getActiveResourcesInfo()` returning `[]`.
- **The tsconfig specifier fix held.** In a clean clone with the pnpm build-approval blocker
  bypassed, all thirteen check steps pass with no prior `dist`: identity, headers, emoji,
  organization, mirror, lint, modules, typecheck, test, build, exports, pack, publish.
- **`findPlacements` cannot produce overlapping or out-of-order ranges** - `matchAll` on a global
  regex cannot - so compose's unguarded slicing is safe, though it asserts nothing itself.
  Nested directives, an attribute value containing `>`, an uppercase attribute name and
  single-quoted attributes are all refused rather than half-understood.
