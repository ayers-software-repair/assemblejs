# B-02 / B-02b adversarial verification

Target: branch `next`, commit `65a08ff` ("feat(core): the package shell, and every organization
rule as a gate"). Verified by a fresh reader, read-and-run only; no repo file was modified.

All mutation experiments ran in throwaway copies of the tree under the session scratchpad
(`scratch2` pinned to `65a08ff`, `scratch3` at `65a08ff` with the leftover import removed).

## Verdict

The commit does not do what its message says. Commit `65a08ff` cannot pass `pnpm check`, and it
fails for two independent reasons, either of which is on its own disqualifying. First, the
committed `packages/core/src/client/mount-handle.ts` still carries the probe line
`import "../compose/limits.js";` that was used to red-test dependency-cruiser; that line trips
`client-stays-browser-only`, and the only place it is removed is an uncommitted working-tree edit.
Second, and worse because it survives that fix, `pnpm check` runs `lint` fifth and `check:modules`
sixth but `build` ninth, while both of those gates silently require `packages/core/dist` to exist.
On a fresh checkout the chain dies at `eslint .` with 16 `import-x/order` errors, before
dependency-cruiser is ever reached. The green run the message rests on was obtained on a tree that
already had a `dist/` from an earlier build, so "their proof is one green run of pnpm check" is a
claim about a machine state, not about the commit.

Those two failures are one story. `pnpm check` is not a function of the commit; it is a function of
the commit plus whatever `dist/` happens to be sitting on disk. That is why the author's green run
and this verification's red run are both honest reports of what each machine did. It is also how
the probe import in finding 2 survived: with a stale `dist/` present, dependency-cruiser passed on
the tree as it stood before the probe was added, and nothing re-ran it afterwards.

The organization gate is also substantially more porous than the commit implies. It reads
declarations off the AST, but it only counts a declaration when the `export` keyword appears as a
_modifier_; `export { x }` and `export default <expr>` are separate node kinds where `export` is
syntax rather than a modifier, so both slip past. That single gap defeats rule 1 and rule 2. Rule 3's
second clause is not implemented at all, and rule 4 only inspects specifiers beginning with `.`, so
a module can import the package index by the package's own name and create exactly the index cycle
rule 4 exists to forbid, with check-organization, eslint `import-x/no-cycle`, dependency-cruiser
`no-circular` and `tsc` all reporting clean.

The most serious individual defect is the identity gate's self-test, because it is the one check
whose honesty the repository asserts most loudly. Its `--self-test` re-implements the scan with its
own `grep` against the fixture directory instead of exercising the gate's `tracked()` pipeline. A
gate neutered so that it scans zero files still prints its self-test success line and still prints
"identity gate: clean". The script's own comment (lines 28-31) says this block exists precisely to
catch a refactor that makes the flag print success without running anything; it does not catch it.

By contrast the organization and mirror self-tests are honest, the sixteen tests are real runtime
assertions rather than type-shape placeholders, `check-exports` genuinely catches a declared subpath
whose target is missing, and `attw` genuinely catches a corrupted built type surface. The work is
not hollow. It is over-claimed, and it was reported done from a tree state that no longer matches
what was committed.

## Organization rules checked by hand, not by the gate

Rules 1, 2, 6 and 7 hold across all 22 files in `packages/core/src`. Every leaf exports exactly one
name and the filename is its kebab form; all six `index.ts` files re-export only; there is no drawer
directory; the largest file is well under the 300-line ceiling. Rule 3 holds including its second
clause: `src/index.ts` re-exports `contract`, `json` and `compose`, and correctly omits `renderer`
and `client` because each is its own published subpath. Rule 4 holds: every relative import in the
tree names a leaf `.js`. Rule 5 holds: 16 sources, 16 mirroring tests, correct paths.

No file violates a rule the gate passed. The tree is compliant; the gates are what is porous.

## What is genuinely solid

- The organization and mirror self-tests are honest. Stubbing `checkTree` to `return []` gives
  `organization gate self-test FAILED: rule(s) 1, 2, 3, 4, 6, 7 did not fire`, exit 1; stubbing
  `checkPair` to `return []` gives `mirror gate self-test FAILED: it must catch both a missing test
and an orphan`, exit 1. Both go red on a broken gate, which is the property that matters.
- The rule-3 fix described in the commit is real and correct. Keying on `dirname(path) === root`
  rather than on the path spelling `src/index.ts` is what makes the fixture reachable, and the
  comment at lines 102-104 explains it accurately.
- check-organization's rule 1, rule 4 and rule 6 fire correctly on the ordinary forms, with
  precise messages naming the rule and the fix.
- check-exports does catch a declared subpath whose target is missing:
  `@assemblejs/core: declares "./renderer" but it does not resolve (MODULE_NOT_FOUND)`. The brief's
  suspicion does not land here.
- `attw` is a real gate on the built type surface, and the only one: it exits 1 on a corrupted
  emitted chunk that `tsc`, `publint` and `check:exports` all pass.
- The 16 tests are real runtime assertions, not type-shape placeholders. They construct values and
  assert behaviour, including JSON round-trips and a renderer that must throw rather than return
  error markup. 18 tests over 16 files, all passing.
- `check-pack` genuinely gates. With `sourcemap: true` it refuses the tarball on three `.map`
  paths and exits 1, which is precisely the regression the tsup comment says it guards.
- The eslint `import-x/extensions` configuration is right for NodeNext, and the reasoning recorded
  for disabling `noUselessIndex` is sound.
- The layering rules in `.dependency-cruiser.cjs` are well chosen, and `client-stays-browser-only`
  does fire on exactly the violation it was written for, as finding 2 demonstrates.

## Recommended order of repair

1. Commit the `mount-handle.ts` revert; the working tree already holds it.
2. Reorder `check` so `build` precedes `lint` and `check:modules`, or make both resilient to an
   absent `dist`. Prove it by deleting `packages/core/dist` and running `pnpm check` from cold.
3. Rewrite `identity-gate.sh --self-test` to invoke the gate's real path against the fixture tree
   and require a non-zero exit, rather than grepping the fixtures itself.
4. Extend `declaredExports` to count `ExportDeclaration` without a module specifier and
   `ExportAssignment`, then re-run the fixture self-test with those forms added to it.
5. Widen rule 4 to relative specifiers and the package's own name, and add the index-cycle case to
   `organization-bad`.
6. Anchor the mirror exemption on the basename, not the path suffix.
7. Either wire `knip` and `syncpack` into `check` or stop claiming them in CLAUDE.md.
