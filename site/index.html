One page. Every framework.

Build one application from UI assemblies written in React, Vue, Svelte and more. AssembleJS composes their HTML on the server and hydrates each in its own framework. Assemblies can live in your project or on another server; page events connect their interactions.

A directory is an assembly

Make a directory, put a view in it, and it exists. Nothing to register, no import to add, no list restating your own folder tree. Your server file never grows.

The file name says the framework

cart.svelte, cart.react.tsx. A directory listing tells you what a page is made of, so nobody has to read a config to find out.

One slow assembly is not a slow page

Every assembly carries a deadline and a fallback. A dead one degrades to its last good content and the page still ships, in the template's order.

They talk without adapters

A typed event bus that belongs to the page rather than to any framework's tree, so a React assembly and a Svelte one exchange messages with nothing in between.

An assembly can live anywhere

Give one a URL and another team serves it. Moving it changes a URL and nothing else: the same deadline, the same fallback, the same headers.

Your agent knows the framework

An MCP server ships with it, so an AI agent reads your project, adds an assembly, places it, checks its own work against the framework's rules, and renders what it made to see what it actually produced: any view through your running dev server, plain HTML with nothing running. Every new project is written with the instructions that tell an agent so, and with the server installed and registered. It carries no model and no key of its own.
