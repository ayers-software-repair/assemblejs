Getting started

An assembly is a piece of a page written in one framework. A page places assemblies. That is the whole model, and the rest of this page is how you write one.

Your first assembly

A directory is an assembly
Make src/assemblies/cart/cart.svelte and you have an assembly called cart. There is nothing to register: no import to add, no array to append to, no list restating the directory tree. Your server file does not grow.
The file name says which framework
cart.svelte and cart.vue need no help. Where an extension is shared, the name carries it: cart.react.tsx, cart.preact.tsx, cart.solid.tsx. A directory listing tells you what a page is made of.
Put it on a page
Write <assembly name="cart"></assembly> in a page template. The server replaces it with the rendered assembly.

Adding a second framework

assemblejs add assembly checkout --renderer react
One command and one tag. The React developer and the Svelte developer work on the same page without either learning the other's framework.
They talk through the page
Every assembly gets a typed events object scoped to it. One sends, another listens, and neither needs an adapter, because the bus belongs to the page rather than to any framework's tree.

Working with an agent

The project says what it is
A new project carries an AGENTS.md, the file Claude Code, Cursor and VS Code look for: what a page, an assembly and a placement are, how to change the project, and every rule its code must satisfy.
And hands over the framework's own tools
The project's MCP server is installed with it and registered for each of them. An agent adds an assembly, places it, and composes the page to see what it made, with no server started. npx assemblejs check holds the instructions to the version you installed, and npx assemblejs add agents rewrites them.
Ask for the common things by name
The server lists four prompts, which Claude Code and VS Code show as commands and Cursor supports as well: add an assembly, place one, make a page, fix what check finds. Each briefs the agent the framework's way: look before adding, ask where it was not told, and check last.

When one of them is slow

Every assembly has a deadline
A slow or dead assembly renders its declared fallback, or the last good content, and the page still ships. One failing assembly is one failing assembly.
