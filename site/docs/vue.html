For Vue developers

A Vue assembly is a single-file component. The server renders it, the browser hydrates it, and the page it sits on can hold React or Svelte beside it. Everything on this page is from the repository's own examples, its design document or its tests.

Install the renderer

npm install @assemblejs/renderer-vue vue
The renderer and Vue itself, 3.4 or newer; the build compiles your components with the project's own Vue, so it has to be there.

The view

npx assemblejs add assembly cart --renderer vue
Writes src/assemblies/cart/cart.vue and nothing else. The extension says the framework, and the directory is the assembly: nothing to register. 
<script setup lang="ts">
defineProps<{ data: Record<string, unknown> }>();
</script>

<template>
  <p>cart {{ Object.keys(data).length }}</p>
</template>
One prop, nothing else
data is what the assembly's services returned, as JSON. No request, no headers, no cookies cross to the component, and nothing of the assemblies it holds: it places those with a slot.
An assembly inside this one
Slot places another assembly where it stands, by name, whatever that assembly is written in. The server puts it there, and the page's runtime mounts it as it mounts this one; Vue leaves it alone when this component renders again. The name is written as a string. A view may be bound to data. 
<script setup lang="ts">
import { Slot } from "@assemblejs/renderer-vue/client";
</script>

<template>
  <section class="cart">
    <Slot name="price" />
  </section>
</template>

Data from the server

cart.service.ts
A service beside the view runs on the server before the render and returns the data. It is given the request's query and the route params of the page that placed the assembly, and the same function answers the assembly's data endpoint. 
import { defineService } from "@assemblejs/core";

export default defineService({
  name: "label",
  schema: { properties: { label: { type: "string" } }, required: ["label"] },
  run: () => ({ label: "Clicked" }),
});

Talking to the rest of the page

useEvents()
From @assemblejs/renderer-vue/client. The object is scoped to this assembly: send stamps the sender and on returns its unsubscribe. Subscribe when mounted and stop when unmounted; what is still subscribed when the page unmounts its assemblies is released then. A React or Svelte assembly on the same page hears the same message, with no adapter between them. 
<script setup lang="ts">
import { useEvents } from "@assemblejs/renderer-vue/client";
import { onMounted, onUnmounted, ref } from "vue";

const events = useEvents();
const count = ref(0);
const heard = ref("nothing");
let stop = (): void => undefined;
onMounted(() => {
  stop = events.on("counted", (message) => (heard.value = message.from.name));
});
onUnmounted(() => stop());

const bump = (): void => {
  count.value += 1;
  events.send("counted", { count: count.value });
};
</script>

<template>
  <section>
    <button type="button" class="bump" @click="bump">vue {{ count }}</button>
    <span>{{ heard }}</span>
  </section>
</template>

<style scoped>
.bump {
  color: rgb(0, 120, 60);
}
</style>
events.last(topic)
A page can name one stream, and every topic the stream sends keeps its last message. An assembly that mounts after the stream opened reads what it missed with last, then subscribes.

When it runs in the browser

export const mount = "visible"
Written in a plain <script lang="ts"> block beside the <script setup>, because a setup script cannot export a name. load mounts at once and is the default; idle waits for the browser to be idle; visible waits until the envelope scrolls into view; none never mounts: the runtime reads the mode and leaves the assembly as the server sent it, and the page still carries the runtime for the rest. export const shadow = true in the same block renders it in its own shadow root. 
<script lang="ts">
export const mount = "visible";
</script>

<script setup lang="ts">
defineProps<{ data: Record<string, unknown> }>();
</script>

Styles

<style scoped>
Vue's own scoping works as it does anywhere. A cart.css beside the component is scoped by the build instead, with a scope derived from the assembly's name, and every file it names beside it is built with it.

On a page

<assembly name="cart"></assembly>
In any page template under src/pages. A local placement needs no policy at all.
home.page.ts
Policy, when a placement needs any, lives in the page's own file: a deadline in milliseconds, markup to show when the assembly does not answer, whether its failure fails the page, or a deferral the browser fills after load. 
import { definePage } from "@assemblejs/core";

export default definePage({
  place: { cart: { deadline: 500, fallback: "<p>Cart unavailable</p>" } },
});

Run it

npm run dev
Builds, starts, and rebuilds on every change.
npx assemblejs check
Every problem found without building, Vue not being installed among them.
npx assemblejs build
Writes dist/server.js and the browser files. Production is node dist/server.js with no bundler.
