For React developers

A React assembly is a component in a file whose name says it is React. The server renders it, the browser hydrates it, and the page it sits on can hold Svelte or Vue beside it. Everything on this page is from the repository's own examples, its design document or its tests.

Install the renderer

npm install @assemblejs/renderer-react react react-dom
One renderer package per framework, so a project that has no Vue never installs Vue. React 18.3 or newer.

The view

npx assemblejs add assembly cart --renderer react
Writes src/assemblies/cart/cart.react.tsx and nothing else: the directory is the assembly, and the .react infix says the framework, because .tsx alone could be Preact or Solid. Your server file does not change. 
import type { AssemblyProps } from "@assemblejs/renderer-react";

export default function Cart({ data }: AssemblyProps) {
  return <p>cart {Object.keys(data).length}</p>;
}
Two props, nothing else
data is what the assembly's services returned, as JSON. children is rendered HTML by placement name, for an assembly that holds others. No request, no headers, no cookies cross to the component.

Data from the server

cart.service.ts
A service beside the view runs on the server before the render and returns the data. It is given the request's query and the route params of the page that placed the assembly, and the same function answers the assembly's data endpoint, so the two cannot disagree. 
import { defineService } from "@assemblejs/core";

export default defineService({
  name: "tag",
  schema: { properties: { sku: { type: "string" } }, required: ["sku"] },
  run: ({ params }) => ({ sku: params["sku"] ?? "none" }),
});
Read it as a prop
The component types what it reads. A page at /item/:sku gives this service { sku: "a1" }. 
export default function Tag(props: { readonly data: { readonly sku: string } }) {
  return <p className="tag">{props.data.sku}</p>;
}

Talking to the rest of the page

useEvents()
From @assemblejs/renderer-react/client. The object is scoped to this assembly: send stamps the sender, on returns its unsubscribe, so returning it from an effect is the whole cleanup; what is still subscribed when the page unmounts its assemblies is released then. A Svelte counter on the same page sends; this React readout hears, with no adapter between them. 
import { useEvents } from "@assemblejs/renderer-react/client";
import { useEffect, useState } from "react";

export const mount = "visible";

export default function Readout() {
  const events = useEvents();
  const [heard, setHeard] = useState("nothing yet");
  useEffect(
    () =>
      events.on("counted", (message) =>
        setHeard(`${message.from.name} counted ${String((message.payload as { count: number }).count)}`),
      ),
    [events],
  );
  return <p id="readout">{heard}</p>;
}
events.last(topic)
A page can name one stream, and every topic the stream sends keeps its last message, because the stream opens while assemblies are still loading. An assembly that mounts late reads what it missed with last, then subscribes. 
useEffect(() => {
  const last = events.last("price");
  if (last !== undefined) setPrice(JSON.stringify(last.payload));
  return events.on("price", (message) => setPrice(JSON.stringify(message.payload)));
}, [events]);

When it runs in the browser

export const mount = "visible"
Declared by the view. load mounts at once and is the default; idle waits for the browser to be idle; visible waits until the envelope scrolls into view; none never mounts, and the assembly ships no JavaScript at all.
export const shadow = true
Renders the assembly in its own shadow root: no page style reaches in, none of its own leaks out.

Styles

cart.css
A stylesheet beside the view is compiled with a scope derived from the assembly's name, so two assemblies written apart cannot collide. Every file it names beside it, an image or a font, is built with it; one it cannot carry is a build problem, not a broken link found later.

On a page

<assembly name="cart"></assembly>
In any page template under src/pages. A local placement needs no policy at all.
home.page.ts
Policy, when a placement needs any, lives in the page's own file: a deadline in milliseconds, markup to show when the assembly does not answer, whether its failure fails the page, or a deferral the browser fills after load. A route with a parameter reaches the services as params. 
import { definePage } from "@assemblejs/core";

export default definePage({
  route: "/item/:sku",
  place: {
    cart: { deadline: 500, fallback: "<p>Cart unavailable</p>" },
    tag: { defer: true },
  },
});

Run it

npm run dev
Builds, starts, and rebuilds on every change.
npx assemblejs check
Every problem found without building: a placement naming an assembly that does not exist, policy nothing reads, a renderer not installed, a budget that is not whole bytes.
npx assemblejs build
Writes dist/server.js and the browser files. Production is node dist/server.js with no bundler.
