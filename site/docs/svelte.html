For Svelte developers

A Svelte assembly is a component, Svelte 5 and runes. The server renders it, the browser hydrates it, and the page it sits on can hold React or Vue beside it. Everything on this page is from the repository's own examples, its design document or its tests.

Install the renderer

npm install @assemblejs/renderer-svelte svelte
The renderer and Svelte 5 itself; the build compiles your components with the project's own compiler, so it has to be there.

The view

npx assemblejs add assembly cart --renderer svelte
Writes src/assemblies/cart/cart.svelte and nothing else. The extension says the framework, and the directory is the assembly: nothing to register. 
<script lang="ts">
  let { data } = $props();
</script>

<p>cart {Object.keys(data).length}</p>
The data, and the events
data is what the assembly's services returned, as JSON. events is this assembly's own events object, handed in as a prop. No request, no headers, no cookies cross to the component, and nothing of the assemblies it holds: it places those with a slot.
An assembly inside this one
slot() answers the markup that places another assembly, by name, whatever that assembly is written in, for Svelte's own raw form to write. The server puts the assembly there, and the page's runtime mounts it as it mounts this one; Svelte leaves it alone when this component renders again. The name is written as a string. An assembly in a project has one view, so the second argument, which names one, is left out. 
<script lang="ts">
  import { slot } from "@assemblejs/renderer-svelte/client";
</script>

<section class="cart">{@html slot("price")}</section>

Data from the server

cart.service.ts
A service beside the view runs on the server before the render and returns the data. It is given the request's query and the route params of the page that placed the assembly, and the same function answers the assembly's data endpoint. 
import { defineService } from "@assemblejs/core";

export default defineService({
  name: "label",
  schema: { properties: { label: { type: "string" } }, required: ["label"] },
  run: () => ({ label: "Clicked" }),
});
Read it as a prop
The counter from the two-frameworks example reads its label from the service and sends an event on every click. 
<script lang="ts">
  let { data, events } = $props();
  let count = $state(0);
</script>

<button type="button" onclick={() => { count += 1; events.send("counted", { count }); }}>
  {data.label} {count}
</button>

Talking to the rest of the page

events
The prop is scoped to this assembly: send stamps the sender and on returns its unsubscribe, so returning it from $effect is the whole cleanup; what is still subscribed when the page unmounts its assemblies is released then. A React or Vue assembly on the same page hears the same message, with no adapter between them. 
<script lang="ts">
  let { events } = $props();
  let count = $state(0);
  let heard = $state("nothing");
  $effect(() => events.on("counted", (message) => (heard = message.from.name)));
</script>

<section>
  <button type="button" onclick={() => { count += 1; events.send("counted", { count }); }}>
    svelte {count}
  </button>
  <span>{heard}</span>
</section>
events.last(topic)
A page can name one stream, and every topic the stream sends keeps its last message. An assembly that mounts after the stream opened reads what it missed with last, then subscribes. 
<script lang="ts">
  import { onMount } from "svelte";

  let { events } = $props();
  let price = $state("waiting");
  onMount(() => {
    const last = events.last("price");
    if (last !== undefined) price = JSON.stringify(last.payload);
    return events.on("price", (message) => (price = JSON.stringify(message.payload)));
  });
</script>

<p>{price}</p>

When it runs in the browser

export const mount = "visible"
Written in the component's module script, <script module>. load mounts at once and is the default; idle waits for the browser to be idle; visible waits until the envelope scrolls into view; none never mounts: the runtime reads the mode and leaves the assembly as the server sent it, and the page still carries the runtime for the rest. export const shadow = true in the same script renders it in its own shadow root. 
<script module lang="ts">
  export const mount = "visible";
</script>

<script lang="ts">
  let { data } = $props();
</script>

Styles

<style>
Svelte's own scoping works as it does anywhere. A cart.css beside the component is scoped by the build instead, with a scope derived from the assembly's name, and every file it names beside it is built with it.

On a page

<assembly name="cart"></assembly>
In any page template under src/pages. A local placement needs no policy at all.
home.page.ts
Policy, when a placement needs any, lives in the page's own file: a deadline in milliseconds, markup to show when the assembly does not answer, whether its failure fails the page, or a deferral the browser fills after load. 
import { definePage } from "@assemblejs/core";

export default definePage({
  place: { cart: { deadline: 500, fallback: "<p>Cart unavailable</p>" } },
});

Run it

npm run dev
Builds, starts, and rebuilds on every change.
npx assemblejs check
Every problem found without building, Svelte not being installed among them.
npx assemblejs build
Writes dist/server.js and the browser files. Production is node dist/server.js with no bundler.
