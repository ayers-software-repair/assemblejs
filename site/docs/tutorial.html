Documentation / The tutorial

The tutorial

One project, from nothing to a deployed server, in the order you would actually do it. Each step is one command or one file, and every file here is taken from the repository's own examples, its design document or its tests.

1. Make a project

npm create @assemblejs shop
Writes a project that runs: a page, one assembly, a server file that will never grow, and a package.json whose one runtime dependency is @assemblejs/core, the command and the agent surface being development dependencies. Beside them, for an AI agent that opens the project: an AGENTS.md that says what the project is and the rules its code must satisfy, and the project's own MCP server registered for Claude Code, Cursor, VS Code, Gemini CLI and opencode.
cd shop && npm install && npm run dev
Builds, starts, prints the address, and rebuilds on every change.
What is in it
src/pages/home/home.html is the page, a template that places one assembly; src/assemblies/hello/hello.html is that assembly, a plain template with no framework. 
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>shop</title>
  </head>
  <body>
    <assembly name="hello"></assembly>
  </body>
</html>

2. Add an assembly in your framework

npx assemblejs add assembly counter --renderer svelte
Writes src/assemblies/counter/counter.svelte and prints the tag that places it. Install the renderer it needs: npm install @assemblejs/renderer-svelte svelte. The guides for React and Vue show the same step in those idioms.
<assembly name="counter"></assembly>
Add the tag to the page's template, below the first. The server now renders both, each with its own renderer, into one document.

3. Give it data

src/assemblies/counter/counter.service.ts
A service beside the view returns the assembly's data. It runs on the server before the render and also answers the assembly's data endpoint, so the two can never disagree. 
import { defineService } from "@assemblejs/core";

export default defineService({
  name: "label",
  schema: { properties: { label: { type: "string" } }, required: ["label"] },
  run: () => ({ label: "Clicked" }),
});
Read it in the view
The view receives data and its own events as props. 
<script lang="ts">
  let { data, events } = $props();
  let count = $state(0);
</script>

<button type="button" onclick={() => { count += 1; events.send("counted", { count }); }}>
  {data.label} {count}
</button>

4. Let two frameworks talk

npx assemblejs add assembly readout --renderer react
Then npm install @assemblejs/renderer-react react react-dom, and the tag on the page. The readout hears what the Svelte counter sends, because the bus belongs to the page and not to either framework's tree. 
import { useEvents } from "@assemblejs/renderer-react/client";
import { useEffect, useState } from "react";

export default function Readout() {
  const events = useEvents();
  const [heard, setHeard] = useState("nothing yet");
  useEffect(
    () =>
      events.on("counted", (message) =>
        setHeard(`${message.from.name} counted ${String((message.payload as { count: number }).count)}`),
      ),
    [events],
  );
  return <p>{heard}</p>;
}

5. Serve some data of your own

src/api/time.api.ts
An api is a route. GET unless method says otherwise; the handler is given the request's query, its route params and its parsed body, and what it returns is the JSON reply. 
import { defineApi } from "@assemblejs/core";

export default defineApi({ path: "/api/time", handle: () => ({ now: new Date().toISOString() }) });

6. Decide what happens when an assembly is slow

src/pages/home/home.page.ts
Policy lives beside the page's template, only for the placements that need any. A deadline in milliseconds; the markup shown when the assembly does not answer; or that its failure fails the page. A slow assembly renders its fallback and the page still ships. 
import { definePage } from "@assemblejs/core";

export default definePage({
  place: {
    counter: { deadline: 500, fallback: "<p>Counter unavailable</p>" },
  },
});
defer: true
For an assembly that must not hold the page at all: the server ships its placeholder and the browser fetches it after load. A route with a parameter reaches the deferred assembly's services as params, exactly as it reaches one rendered with the page. 
import { definePage } from "@assemblejs/core";

export default definePage({ route: "/item/:sku", place: { tag: { defer: true } } });

7. Push live data to every page

src/api/prices.api.ts
An api with stream in place of handle holds its response open and sends events; the browser opens one connection per page and puts each message on the page's bus, where assemblies receive it like any other event. 
import { defineApi } from "@assemblejs/core";
import { priceFeed } from "./price-feed.js";

export default defineApi({
  path: "/api/prices",
  stream: ({ send, signal }) => {
    send("price", priceFeed.latest);
    priceFeed.listening.add(send);
    signal.addEventListener("abort", () => priceFeed.listening.delete(send));
  },
});
definePage({ stream: "/api/prices" })
The page names its one stream. An assembly that mounts after the stream opened reads the last message with events.last("price"), then subscribes.

8. Check it, then weigh it

npx assemblejs check
Every problem found without building: a tag naming an assembly that does not exist, policy for a placement the template never makes, a stream that is no stream, a renderer not installed, a template that does not compile. The same findings the agent surface reports.
npx assemblejs perf
Builds, starts the built server in production, and reports what each page sends a visitor before anything mounts. Budgets in assemblejs.config.ts are gzipped bytes by part, and a page over one fails the command. 
import { defineConfig } from "@assemblejs/core";

export default defineConfig({
  budgets: { document: 20000, styles: 10000, scripts: 60000 },
});
src/tokens.css holds the project's tokens, the colour roles, distances, type sizes and corners every assembly's stylesheet reads; every page links it first, and the look of the project is changed in that one place. src/components.css beside it styles the elements HTML already has, the button, the field, the list, the table, the notice and the dialog, each a class and the tokens, for every kind of view to use. The same file sets limits, how deep composition goes and how many placements one request composes, when the defaults of 8 and 256 do not fit: limits: { depth: 4, placements: 100 }. A value outside its bounds refuses to boot.

9. Ship it

npx assemblejs build
Writes dist/server.js and its browser files. node dist/server.js runs it; ASSEMBLEJS_PORT and ASSEMBLEJS_HOST say where, and ASSEMBLEJS_MODE=development turns the development behaviour back on.
npx assemblejs deploy
Builds, then writes deploy/: the build and a package.json of the project's dependencies alone. Install there and npm start runs the same server. Where the directory goes is yours.
