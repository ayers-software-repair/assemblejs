For Preact developers

A Preact assembly is a component in a file whose name says it is Preact. The server renders it, the browser hydrates it, and the page it sits on can hold React or Svelte beside it. Everything on this page is from the repository's own examples, its conformance fixtures, its design document or its tests.

Install the renderer

npm install @assemblejs/renderer-preact preact
One renderer package per framework, so a project that has no React never installs React. Preact 11; the renderer's own machinery, preact-render-to-string, comes with it.

The view

npx assemblejs add assembly cart --renderer preact
Writes src/assemblies/cart/cart.preact.tsx and nothing else: the directory is the assembly, and the .preact infix says the framework, because React, Preact and Solid all write .tsx. Your server file does not change. 
import type { AssemblyProps } from "@assemblejs/renderer-preact";

export default function Cart({ data }: AssemblyProps) {
  return <p>cart {Object.keys(data).length}</p>;
}
Two props, nothing else
data is what the assembly's services returned, as JSON; AssemblyProps takes its shape as a type argument. children is rendered HTML by placement name, for an assembly that holds others. No request, no headers, no cookies cross to the component.
A component beside it
A file in the assembly's directory with no framework in its name compiles as Preact, because its assembly is one; the build names the JSX runtime for each file from the framework its name says, else from the assembly whose directory holds it. 
// A component with no framework in its name: it compiles as Preact because its assembly is one.
export function Label({ count }: { readonly count: number }) {
  return <>preact {count}</>;
}

Data from the server

cart.service.ts
A service beside the view runs on the server before the render and returns the data. It is given the request's query and the route params of the page that placed the assembly, and the same function answers the assembly's data endpoint, so the two cannot disagree. The component reads the result as data. 
import { defineService } from "@assemblejs/core";

export default defineService({
  name: "label",
  schema: { properties: { label: { type: "string" } }, required: ["label"] },
  run: () => ({ label: "Clicked" }),
});

Talking to the rest of the page

useEvents()
From @assemblejs/renderer-preact/client; the hooks are Preact's own, from preact/hooks. The object is scoped to this assembly: send stamps the sender, on returns its unsubscribe, so returning it from an effect is the whole cleanup; what is still subscribed when the page unmounts its assemblies is released then. The counter from the frameworks example sends on every click and hears every other counter on the page, React, Svelte, Vue, Solid or Lit, with no adapter between them. 
import { useEvents } from "@assemblejs/renderer-preact/client";
import { useEffect, useState } from "preact/hooks";
import { Label } from "./label.js";

export default function PreactCounter() {
  const events = useEvents();
  const [count, setCount] = useState(0);
  const [heard, setHeard] = useState("nothing");
  useEffect(() => events.on("counted", (message) => setHeard(message.from.name)), [events]);
  return (
    <section>
      <button
        type="button"
        id="preact-bump"
        onClick={() => {
          setCount(count + 1);
          events.send("counted", { count: count + 1 });
        }}
      >
        <Label count={count} />
      </button>
      <span id="preact-heard">{heard}</span>
    </section>
  );
}
On the server
The component renders inside the same events context it hydrates inside, holding the server's events, so a component that calls useEvents() renders on the server as in the browser: a subscription made there is accepted and never called, and last answers nothing.
events.last(topic)
A page can name one stream, and every topic the stream sends keeps its last message, because the stream opens while assemblies are still loading. An assembly that mounts late reads what it missed with last, then subscribes.

When it runs in the browser

export const mount = "idle"
Declared by the view. load mounts at once and is the default; idle waits for the browser to be idle; visible waits until the envelope scrolls into view; none never mounts: the runtime reads the mode and leaves the assembly as the server sent it, and the page still carries the runtime for the rest. A value that is none of the four reads as none, so a typo cannot start code running on a page whose author was saying when it should run. 
// Mounted when the browser is idle.
export const mount = "idle";

export default function IdleLabel() {
  return <p class="label">mounts when idle</p>;
}
export const shadow = true
Renders the assembly in its own shadow root: no page style reaches in, none of its own leaks out. The box from the shadow example, where every framework counts in a root of its own. 
import { useState } from "preact/hooks";

export const shadow = true;

export default function PreactBox() {
  const [count, setCount] = useState(0);
  return (
    <button type="button" class="bump" id="preact-bump" onClick={() => setCount(count + 1)}>
      preact {count}
    </button>
  );
}

Styles

cart.css
A stylesheet beside the view is compiled with a scope derived from the assembly's name, so two assemblies written apart cannot collide; the view in its own shadow root links a second sheet, built for that root. Every file it names beside it, an image or a font, is built with it; one it cannot carry is a build problem, not a broken link found later. The box above writes class, as Preact reads it, and its sheet beside it is one rule. 
.bump {
  color: rgb(0, 128, 0);
}

On a page

<assembly name="cart"></assembly>
In any page template under src/pages. A local placement needs no policy at all.
home.page.ts
Policy, when a placement needs any, lives in the page's own file: a deadline in milliseconds, markup to show when the assembly does not answer, whether its failure fails the page, or a deferral the browser fills after load. 
import { definePage } from "@assemblejs/core";

export default definePage({
  place: { cart: { deadline: 500, fallback: "<p>Cart unavailable</p>" } },
});

Run it

npm run dev
Builds, starts, and rebuilds on every change.
npx assemblejs check
Every problem found without building: a placement naming an assembly that does not exist, policy nothing reads, the renderer not installed, a view named cart.tsx, which does not say its framework.
npx assemblejs build
Writes dist/server.js and the browser files. Production is node dist/server.js with no bundler.
