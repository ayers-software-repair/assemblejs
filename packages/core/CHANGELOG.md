## 1.0.0-next.0

### Major Changes

- The first prerelease on the next channel: the server, the command line and create, the agent surface, the devtools, the renderers for React, Preact, Vue, Svelte, Solid and Lit, and the template renderer for EJS, Handlebars, Markdown, Nunjucks and Pug.

### Minor Changes

- One request composes no more than `limits.placements` placements, 256 by default, at every depth together: a page's own and those of every view composed for it in this process. A placement answered from the cache is one, whatever that answer holds, and at an assembly's own address the assembly asked for is not counted. A placement numbered past the limit is refused before anything is dispatched for it, as one too deep or its own ancestor is: its fallback, with the new reason `too-many`. A deferred placement counts and is not refused. A request the browser fills a deferred placement with, and a request to another server, each have a count of their own.
  
  Every placement a request refuses so carries one correlation id, and the request has one diagnostic for them all, which says how many in its new field `refused`, and one line in the log.
  
  `Limits` gains the required field `placements`, and `DEFAULT_LIMITS` gives it. The count of a request is a `PlacementCount`, made by `countPlacements`: `ComposeOptions`, `AssemblyRequest` and `LocalRenderInput` take one as `count`, and the local transport hands it on to what it renders. `SettleInput` carries it, and a placement's `ordinal`.
- A page that places an assembly from another server links the browser files of every assembly that server composed inside its answer, as it links the answer's own: the transport reads each one's manifest once per version of the server's output. `markRemote` names what an answer holds inside it, and `learnedManifests` keeps it for the url that was asked.
- A page links the stylesheets and modules of every assembly of this server in the markup it serves, at any depth: a child a view placed is styled and mounted as its parent is, and one inside an answer that came from the cache keeps its sheet. A shadow assembly links, inside its own root, the stylesheets of the children placed there. `localAssets(html, assemblies)` is that reader, and `LocalRenderInput` carries the server's assemblies.
  
  The directive finder reads comments and raw-text elements in one pass, so a `<script` written inside a comment no longer hides the directives after it.
- A view places a child by writing the directive, and is never handed one. `children` is gone from `MarkupInput`, `RenderInput`, every renderer's `AssemblyProps` and the template engines' locals: a view renders once, and the server puts each child where its directive stood.
  
  A framework view writes the directive with its renderer's slot, by name and an optional view: `<Slot name="cart" />` in React, Preact, Vue and Solid, `{@html slot("cart")}` in Svelte, `${slot("cart")}` in Lit, each imported from the renderer's `/client` entry. A slot writes the same markup on the server and in the browser, so a parent hydrates around the child the server placed and leaves it alone when it renders again. A template view writes `<assembly name="cart"></assembly>` in its own markup, as a page does; Pug writes it as `assembly(name="cart")`. `placementDirective(name, view?)` in `@asmjs/core/client` is the one definition of that markup, and refuses a name or a view that is not a segment.
  
  A Lit view holds a Lit assembly only behind a shadow root, which `export const shadow = true` in that assembly's view gives it. Lit hydrates a view by reading every marker in its tree, so a Lit assembly left in the same tree is refused by name when the view mounts.
  
  The agent rule `children-arrive-as-strings` is replaced by `a-view-places-a-child-with-the-directive`.
- The envelope's attributes, the attribute on its data island, the one on a deferred envelope's fallback and the two headers a content answer carries each have one definition, which the server writes from and the browser, a composing server and the command line read by: `ENVELOPE_ATTRIBUTE`, `ISLAND_ATTRIBUTE`, `FALLBACK_ATTRIBUTE` and `RESPONSE_HEADER`, exported from `@asmjs/core`, the first from `@asmjs/core/client` too. Nothing a server sends or a browser reads changes.
- A project sets how deep composition goes and how many placements one request composes in its config file: `limits: { depth, placements }` in `assemblejs.config.ts`, each a whole number, each optional, one left out keeping the default of 8 and 256. The server reads them at boot and refuses a value outside its bounds. `createServer` takes `limits` in place of `maxDepth`. `check` and the agent surface show them as they show every setting.
- A view places a child as a page does: an `<assembly name="x"></assembly>` directive in a view's rendered markup is composed where it stands, the child in its own envelope inside its parent's. A child is dispatched one level deeper than its parent arrived, with the parent among its ancestors, so a child that is its own ancestor and a chain past the cap are refused before anything is dispatched, on the content endpoint as on a page.
  
  `renderLocal(assembly, view, input)` takes the composition state and answers `{ html, diagnostics }`; `localFetch` and `registerPages` take the server's limits, and `maxDepth` is the one cap for arrival and for every composer. A `Diagnostic` carries its `children`, and a fallback at any depth is logged against its id. An answer holding a failed envelope is never cached. A composition takes a `signal`: once it aborts, no further placement is dispatched.
- What a view places is known before it renders. `AssemblyView.placements` holds what a view's source is known to place, each a name and, where the source writes one, a view. The build reads it from every view and writes it into the registry: the directives of a plain html, EJS, Handlebars or Nunjucks view, and the slots of a React, Preact, Vue, Solid, Svelte or Lit one. A Pug view is read only when it renders.
  
  Boot holds those placements as it holds a page's: a name with no assembly, a view the assembly lacks and a view that leads back to itself are refused before anything listens. A page carries the runtime when an assembly it places, or one beneath it, has a browser half, so a deferral or a stream on a page whose only placement is a plain html parent is no longer refused. A deferred placement is served with the browser files of everything its view is known to place, linked ahead of the answer that brings them.
  
  `check` reports the same, in the file that places it, and three things only it can know: a placement whose name is computed (`a-placement-is-named-where-it-is-written`), an assembly placed inside itself (`an-assembly-is-never-its-own-ancestor`), and a Lit assembly in a Lit view's own tree with no shadow root between them (`lit-holds-lit-behind-a-shadow-root`).
  
  The agent surface renders and composes through the server's own transport: `render_assembly` and `compose_page` show every assembly a view places composed inside it, with the account of each beneath its parent, and say why one fell back. `place_assembly` takes `in`, an assembly whose view receives the placement, in place of a page; a view its author writes as source is not edited, and the answer is the line to write.
- A project can show how its pages are put together. With `outline: true` in `assemblejs.config.ts`, or passed to `createServer`, every page carries a switch at the corner of the window, and a visitor who turns it on sees a box around each assembly that says what it is, where it came from and when: this server, another server, an answer that was kept, a fallback or a deferred placement, how long the server waited for it, and when the browser brought it alive. It is drawn over the page and moves nothing on it, holds under the default content security policy, and is off unless the project turns it on; a server with it off sends the pages it always sent. The module that draws it is published as `@asmjs/core/outline`, and `check` shows the setting with the rest.
- A placement directive inside a declarative shadow root an element writes for itself is refused where the directive is read: the page's stylesheets do not reach into an element's root, so the child belongs in the view's template, outside the element.
- A placement directive inside a paragraph the parser has not closed is refused where the directive is read, by `check`, at boot, by the composer and at a view's render alike: the browser would close the paragraph at the first block the assembly holds and tear the rest of the assembly out of its envelope.
- A remote declared `trusted: true` is given the page's query with each placement, on the content url it is asked at, as this server's own services are given it; every other remote is asked at the bare content url, whatever the visitor typed into the page's address. Every remote is still given the page's route parameters and the headers it declared. `trusted` written as anything but a boolean refuses to boot.
- A project's tokens are one file, `src/tokens.css`, the colour roles, distances, type sizes and corners every assembly's stylesheet reads as custom properties at `:root`. The build carries it whole and unscoped, named by its content, and every page links it before any assembly's sheet: `createServer` takes `styles`, the urls every page links first, and the built project declares the tokens there. A new project starts with the estate's roles, three scales and a dark scheme, each value a placeholder.
- The browser runtime marks an envelope `data-mounted` once its renderer has mounted the assembly, and removes the mark when it unmounts it, so a page, a test or a person can tell a hydrated assembly from one still waiting for its module. The server never writes it.

### Patch Changes

- An assembly is guarded wherever it is placed. The access decision its own address makes is made again, for the visitor asking, of each of this server's assemblies a page or a view places, before the placement is dispatched and before a cached answer is used; refused, it stands as its fallback or an empty envelope marked failed with no id, and nothing is logged. A page open to everyone that places a guarded assembly shows it only to a visitor its address would admit; an assembly meant for everyone is opened by its address, `/assembly/<name>/*`, in `publicRoutes`. The product's own `authenticate` is asked once for each assembly and view a request places, as a `GET` of that address. A deferred placement is left to its address, which the browser asks; a placement on another server is left to that server. The composer takes it as `admit`, an `Admit` the server binds to the request; `FailureReason` gains `access`.
- What a project's author is told now holds in a project. An assembly made from a directory has one view, `default`, so the rule `a-placement-is-named-where-it-is-written` and the fix `check` gives no longer say a view may be computed, which in a project names a view the child does not have. The directive is written closed, `<assembly name="..."></assembly>`, wherever a rule, a finding or a tool's description shows it: an opening tag alone is refused where it is read. What `check` accepts and refuses of a placement is unchanged. The instructions a project is written with carry the two rules' new words, so `check` asks a project written before this to run `assemblejs add agents`.
- A page and an assembly's content endpoint hand their composition the asker's signal, so a request whose asker has left composes nothing further: a child's children, and a child's own beneath a parent's deadline, are refused before dispatch with the reason `aborted` in place of `timeout`, and the request accounts for them once, as it does for the placements past its limit, under one id and one log line (`PlacementCount.refuse` takes the reason; `account()` answers one diagnostic a reason). A placement whose settling itself threw, a defect in the composer or in a cache the server was given, now shows its declared fallback or an empty envelope marked failed under one id, and its diagnostic carries what was thrown as `cause`, which the server's log line says; it rendered as nothing before. A placement declared required fails its page in that case too.
- An assembly's content endpoint answers `500` with its fallback envelope when its answer, every child composed inside it, is larger than the server's limit on bytes. A page that placed the assembly already refused such an answer; asked for at its own address, it was sent whole, whatever its size.
- The assembly contract's three endpoints are mounted by `registerAssemblies`, as pages, apis and assets already were by their own functions; `logFallbacks` and `refuseBeforeDispatch` are exported beside them. Nothing a server answers changes.
- Each published entry point names its own specifier in a `@module` comment, which is the name the API reference lists it under. Nothing any of them exports changes.
- What other servers' manifests declared is kept by `learnedManifests`, out of `createRemoteTransport`. Nothing a server asks for or answers changes.
- What a composed page links is collected by `pageAssets`, out of `registerPages`. Nothing a server answers changes.
- The directive finder ignores a placement written inside a `script`, `style`, `textarea` or `title` element, as it ignores one inside a comment, so a child's island can never end an enclosing script early. One segment shape, `SEGMENT`, is read everywhere a name or a view is checked: the finder, boot, and the content url parser.
- The browser runtime finds an assembly placed inside a shadow root: `findEnvelopes` enters each shadow root where it stands, in document order, so a child a shadow assembly's view placed is mounted after its parent. The deferred fill asks for its placement one level deep, as the page's own composer would have, so the children it places are composed from the depth they would have had.
- An api's `handle` and a service's `run` may answer an object whose members are sometimes absent, so a handler that answers one of two shapes is accepted as written, and a member left out is not sent and not given to the view. What cannot cross as JSON, a `Date`, a function or a `bigint`, is still refused.
- A kept answer is the placement's own that asks for it, and what another server's answers name is bounded. An answer was kept with the ids its first composition minted and answered as kept with the same ones: two placements of one kept assembly on a page carried one id, and the browser, which mounts an id once, left the second as markup. Read from the cache, an answer's envelope takes the id its placement was given and each assembly inside it a new one, wherever the old id is written (`reissueIds`). One remote answer could name thousands of assemblies inside it and start a manifest read for every one at once, a log line for every one that failed, and an entry kept for every one that did not: an answer naming more than a page here may place is refused (`markRemote` takes the bound, the server's `limits.placements`), and the manifests kept, the children remembered for one url and the reads in flight each have a bound. `placementCache`'s `read` takes the id the placement was given.
- A cached placement is no longer shown to a visitor who may not be shown what it holds. An open assembly whose view places a guarded one, kept by a page with `cache: { ttl }`, was served from the cache to every visitor after a member, the guarded markup inside it. An answer is now kept with the assemblies it holds (`CachedContent.holds`) and is read for a visitor only when each of them would be shown to that visitor; otherwise the placement is composed again for them.
- Three things about where a placement may stand and how long an answer is kept. A placement after a list item, a description's term or part, or a form begun inside a paragraph is no longer refused as standing in an open paragraph: the parser closes the paragraph at each, as it does at a table in a document that opens with the HTML doctype. A placement in a table outside its cells, or in a `select`, is now refused where the directive is read: the parser moves the envelope out before the table and leaves what the assembly holds behind in it. And a placement's `cache.ttl`, which is milliseconds, is held at boot as its deadline is: one that is not a positive, finite number is a boot problem.
- A script ends where the tokenizer ends it. Inside a `<!--`, a `<script` makes the tokenizer read on past the next `</script`, and a script was read as ending at its first end tag whatever it held: a placement written in what the browser still took for the script's text was found and dispatched, and the assembly's markup put inside the script. `scriptEnd` reads a script's text by the tokenizer's three ways of reading it, and `inertSpans` asks it. Where a tag's name ends is written once, `TAG_NAME_END`, for every reader of tags.
- What a server could only fail at, it refuses before it listens, and a name is read as its author wrote it. A view is one its assembly wrote: `/assembly/cart/constructor/` and every other name an object answers to is a 404 at each endpoint, where one was a logged 500, one an empty 200 and one a manifest for a view that is not there (`declaredView` is the one reading). A content security policy or a version that no response header can carry, one written over several lines most often, is a boot error; it started a server that answered every page with a 500. Services that cannot be ordered (a name twice, an `after` naming nothing, a circle) are a boot error naming the assembly and the view; the order was settled per request, so each of them failed every request instead. An empty `ASSEMBLEJS_HOST` is unset, and so loopback; handed on empty it listened on every interface, and one with a space in it is refused. A url that is not one is answered 400 with the failure body, where the router's own answer repeated the path it was sent. The route parameters a service is handed have no prototype whether or not a parent sent any.
- A service can say the thing its page is for does not exist: `throw new NotFound()`, from `@asmjs/core`. The page then answers 404 with the project's not-found page, the page directory `src/pages/not-found`, which has no route of its own and is also what every address no route claims answers. A project without one answers those with the failure body, under a 404, as before; an address under `/assembly` or `/_assemblejs` always does. `check` names a not-found page that declares a route. An address with a trailing slash now answers as the one without it, `/products/` as `/products`, and access is decided of it the same way, so `/admin/` is guarded as `/admin` is.
- Access is decided of the path as the router reads it, decoded. An encoded spelling of a guarded address, `/%61dmin/users` for `/admin/users`, passed a check or a public route written about the path and was then served, because the check was handed the path as sent. `requestedPath` is the one reading both now make; an encoded slash stays encoded, and a path that does not decode is a 400.
- An api is handed the request's headers and cookies, and may answer with `reply(...)`: a status, headers, cookies, a body or a redirect. A service and a page stay a function of the address and are given none of it.
- An assembly can say which topic keeps its last message: `events.keep(topic)`. An assembly that mounts later reads it with `events.last(topic)`, for messages sent after the call.
- An attribute's value is text. The readers of a view's markup read a tag's attributes as markup: a value holding `<!--` or `<script>` ended every placement after it in silence, one holding a directive's text failed the assembly or, written whole in a single-quoted value, was placed and its markup put inside the attribute. A renderer that escapes only the quote in an attribute, as HTML allows and Solid does, wrote a visitor's value there with its angle brackets. What a tag holds between its name and its end is now inert to every reader (`inertSpans`), and a tag ends where the tokenizer ends it, a `>` inside a quoted value being the value's (`tagEnd`). A `<template-card>` is no longer read as a `<template>`.
- A Lit view that renders nothing can be placed from another server. Lit's server render writes `<?>` where a template is empty, which a browser reads as a comment; the reader of a remote's answer refused it as "markup the browser ignores", so the placement fell back. `<?` is now read as the comment the browser makes of it, up to the next `>`, where nothing in it could be a tag; one that holds a `<`, or never ends, is refused as before.
- Markup is read as the browser reads it, in the time its length takes. A custom element whose name begins like a raw-text element's, `<title-bar>`, `<style-guide>`, `<script-runner>`, `<textarea-autosize>`, was read as that element, never closed, and every `<assembly>` after it was passed over in silence; a tag's name ends at a space, a slash or the tag's end now, and an end tag ends its element whatever it holds after its name. A remote's answer could hide markup, an envelope of its own in it, from the reader that stamps and bounds it: inside MathML's `annotation-xml`, inside a heading in SVG or MathML, and inside an element that hands content back to HTML in SVG only or in MathML only, written in the other. Each is read as the parser reads it or refused (`annotation-xml` in MathML is refused), and an element named `constructor` no longer throws. An answer forty thousand elements deep held the server's one thread for ten seconds, and a template of sixteen thousand scripts took a second on every render; both are read in milliseconds (`OpenElements`, `withinSpans`), and a view that places nothing is not read for placements at all. `startTagRefusal` takes the open elements as an `OpenElements` now, where it took a list of names; `OpenElements` and `withinSpans` are new exports, and `openParagraphs` and `shadowTemplates` take the reading of inert stretches they are to use.
- A page now has one event bus, which a remote server's assemblies join when the project declares that remote `events: true`, as it declares `forward` and `trusted`. A remote not declared stays on a bus of its own, as before.
- `serve(project)` reads the configuration, starts the server and says where it listens. A server that refuses to start, because of a setting in the environment, a project it will not build or an address it cannot listen on, now prints its reason as plain sentences, one for each problem, and the process exits 1, where it printed a stack. A new project's server file is the import and one call.
- `perf` weighs what an assembly fetches as it mounts, and a page with a parameter in its route. It reported only what a page loads before anything mounts: 20.7 kB of script on a page whose React assembly then fetched 218 kB. It now shows two parts, the document, styles and scripts before anything mounts, and, for each assembly the browser mounts on the page that is this server's, its module with what that imports before it runs, each file once across the page, then a total. The module is found in the map the page's entry script holds. `budgets` takes `mount` and `total` beside `document`, `styles` and `scripts`. `addresses` in `assemblejs.config.ts` lists one example address for each page whose route has a parameter, keyed by the route as the page declares it, and `perf` weighs the page there and shows both; `check` asks for it with the rule `a-page-with-a-parameter-names-an-address`, and names an address its route does not answer and one for a route no page has. A page with a parameter and no address is still not weighed, and the line names the key to add. A project with such a page now needs the address, and one whose `total` or `mount` is budgeted is held to the truer figure.
- `compose_page` and `render_assembly` take what a visitor arrives with: `params`, a value for each parameter of the page's route, and `query`. Every placement's request is given them as a page's composer gives them, so a page at `/product/:sku` is shown as one product's. Until now both rendered for nobody, with no value for any parameter, and an agent was shown a page no visitor is. `compose_page` holds the values to the route the page declares: one for a parameter the route has not is refused with the ones it has, and a parameter left out is composed without and said among the problems. The three tools that show a project and change nothing are registered by `registerSeeingTools`, exported beside `registerAuthoringTools`.
  
  `@asmjs/core` exports `routeParameters`, the one reading of the names of a route's parameters. The server's route table, `perf`, which does not weigh a page whose route has one, and the agent surface each read it, where each had told a parameter by itself.
- The mark that says an assembly is live is written when it is. A built project mounts through the renderer that loads each assembly's module when the assembly is due, and `data-mounted` was written when that renderer handed back its handle: on every assembly before its module had arrived, and for good on one whose module never did. A `MountHandle` may now say when its half is live (`mounted`, a promise that rejects where it never will be), `lazyRenderer` says it, and the runtime marks then (`markMounted`). A mount that throws releases what it had subscribed (`mountIsland`); an island holding JSON that is not an object is no payload, where the runtime threw on it and mounted nothing after it; on the bus a handler another handler removed during a send is not called, an assembly that subscribes after it was released adds nothing, and a handler that throws is reported against its assembly while every other listener is still called.
- The page's server now passes on the api calls of an assembly placed from another server, so a remote's browser half no longer needs the other server to allow the page's origin. An assembly's browser half calls its own server's apis as `fetch(api("/api/..."))`, with `api` from `@asmjs/core/client`.
- The `Renderer` and `RenderInput` types and the core's `/renderer` entry point, which nothing called, are removed. A renderer package exports its render function and its browser mount.
