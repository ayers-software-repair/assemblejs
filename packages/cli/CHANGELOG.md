# @asmjs/cli

## 1.0.0-next.0

### Major Changes

- The first prerelease on the next channel: the server, the command line and create, the agent surface, the devtools, the renderers for React, Preact, Vue, Svelte, Solid and Lit, and the template renderer for EJS, Handlebars, Markdown, Nunjucks and Pug.

### Minor Changes

- `check` and the agent surface read nothing outside a project's root. Every file a reader opens is held to the root after each link is followed to where it really leads: a link under the root that leads out of it, a directory that is one, and a view's import that climbs out are not opened, not listed and not followed. Each is a finding by a new rule, `a-project-stays-inside-its-root`, and what it would have said reads `(unread)` in `assemblejs://project`. Before this, a finding could quote what such a file held. `add agents` writes nothing through a link that leads out, and a stylesheet's `url()` written outside its assembly is refused without being looked for. Discovery takes the project's root (`discoverAssemblies(root)`, `discoverPages(root)`, `discoverApis(root)`), the readers that open a file take it too, and `insideRoot`, `readInside`, `leadsOut`, `followLinks` and `OutsideRootError` are the command line's, which the agent surface takes them from.
- `check` and a build read what a Pug view places, from the tree the project's own Pug makes of the template, so a Pug view is held to what every other view is. A name with no assembly, a view the assembly lacks and a view that places itself are findings, and refused at boot. A page that defers a Pug parent links ahead what its children need, and a child with a browser half beneath one counts when a page defers or opens a stream.
  
  A directive a template writes that does not read as it is written, with nothing computed in it, is a finding where it was passed over, in EJS, Handlebars, Nunjucks and Pug. A build refuses a view whose placement cannot be read, as it refuses a template that does not compile. One that does not read only for what the template computes in it is left to its render, as before.
  
  A framework view's slots are read under a namespace as well: `import * as client from "@asmjs/renderer-react/client"` and `<client.Slot name="cart" />`, and the same in Lit, Svelte and Vue. A Vue slot written in kebab case, `<place-here>` for a `Slot` imported as `PlaceHere`, is read too.
  
  New exports: `loadPug`, `pugTree`, `pugMarkup`, `unreadPlacements` and the type `PugCompiler`. `templatePlacements` and `readViewPlacements` take the project's Pug as their last argument.
- A new project is written for the agents that will work in it. `new` writes an `AGENTS.md` that says what a page, an assembly, a placement, a service and an api are, how to ask the project and change it, and every rule its code must satisfy; a `CLAUDE.md` that brings it to Claude Code; and the project's own MCP server, `@asmjs/mcp` as a development dependency, registered in `.mcp.json`, `.cursor/mcp.json` and `.vscode/mcp.json`.
  
  `check` holds them current under a new rule, `agent-instructions-are-current`: the command line's part of `AGENTS.md`, its server in each registration, a `CLAUDE.md` that does not import `AGENTS.md`, and a registered server the project does not depend on. Where the installed `@asmjs/mcp` is built on another version of the command line than the one installed beside it, `check` reports that alone, since nothing is current to both. `assemblejs add agents` writes all of it into a project that has none and rewrites only its own part of each file in one that has.
  
  The rules, `RULES`, `findRule` and `Rule`, are exported from here, where `new` and `check` read them; `agentInstructions`, `agentFiles`, `agentProblems`, `addAgents`, `MCP_REGISTRATIONS` and `AGENT_SERVER` are exported beside them.
- `assemblejs://project` answers a project's whole shape: every page with its route, what it places and the policy it declares; every assembly with its files, what its view places and where it is placed; every api's route; and what the config declares. `assemblejs://assembly/<name>` answers one assembly with every placement of it, and each assembly is listed as a resource of its own. All of it is read from the sources and nothing is run: a value a source computes reads `(computed)`, and what a file that cannot be read would have said reads `(unread)`. The command line exports the reader, `readShape`. An assembly in the project's answer has `client` and `browserHalf` where it had `hasClient`.
- What a view places is known before it renders. `AssemblyView.placements` holds what a view's source is known to place, each a name and, where the source writes one, a view. The build reads it from every view and writes it into the registry: the directives of a plain html, EJS, Handlebars or Nunjucks view, and the slots of a React, Preact, Vue, Solid, Svelte or Lit one. A Pug view is read only when it renders.
  
  Boot holds those placements as it holds a page's: a name with no assembly, a view the assembly lacks and a view that leads back to itself are refused before anything listens. A page carries the runtime when an assembly it places, or one beneath it, has a browser half, so a deferral or a stream on a page whose only placement is a plain html parent is no longer refused. A deferred placement is served with the browser files of everything its view is known to place, linked ahead of the answer that brings them.
  
  `check` reports the same, in the file that places it, and three things only it can know: a placement whose name is computed (`a-placement-is-named-where-it-is-written`), an assembly placed inside itself (`an-assembly-is-never-its-own-ancestor`), and a Lit assembly in a Lit view's own tree with no shadow root between them (`lit-holds-lit-behind-a-shadow-root`).
  
  The agent surface renders and composes through the server's own transport: `render_assembly` and `compose_page` show every assembly a view places composed inside it, with the account of each beneath its parent, and say why one fell back. `place_assembly` takes `in`, an assembly whose view receives the placement, in place of a page; a view its author writes as source is not edited, and the answer is the line to write.
- `check` refuses a literal colour in an assembly's stylesheet, as the rule `a-colour-is-a-token`: a hex colour, a colour function or a named colour in any declaration, a custom property's included, in a project that has `src/tokens.css`; a token, `transparent`, `currentcolor`, a string and a url pass.
- `check` refuses an `input`, a `select` or a `textarea` with no name, in any kind of view, as the rule `a-control-has-a-name` (WCAG 2.2, 3.3.2 and 4.1.2, level A): a `label` for its id or one that may wrap it, an `aria-label`, an `aria-labelledby`, a `title`, a placeholder on a text field or a value on a button input each name it; a spread, a computed type, a hidden, submit, reset or image input and a `button` are left to the render.
- A project can show how its pages are put together. With `outline: true` in `assemblejs.config.ts`, or passed to `createServer`, every page carries a switch at the corner of the window, and a visitor who turns it on sees a box around each assembly that says what it is, where it came from and when: this server, another server, an answer that was kept, a fallback or a deferred placement, how long the server waited for it, and when the browser brought it alive. It is drawn over the page and moves nothing on it, holds under the default content security policy, and is off unless the project turns it on; a server with it off sends the pages it always sent. The module that draws it is published as `@asmjs/core/outline`, and `check` shows the setting with the rest.
- `check` refuses a `style` attribute on any element of any kind of view, written or computed, as the rule `a-view-has-no-inline-style`: a style attribute does nothing under the default content security policy and sets a value where it is used, where the stylesheet and the tokens are the one place a look is set. `viewElements` and `elementProblems` are exported; `readViewElements` reads one file of a view by its kind.
- `check` refuses an `img` with no `alt` at all, in any kind of view, as the rule `an-image-has-an-alternative` (WCAG 2.2, 1.1.1, level A); an empty `alt` passes as decoration, a computed one as present, and an `img` under a spread is left to the render.
- `check` refuses a slot written inside a Lit element's `render`, as the rule `a-placement-stands-outside-an-element`: the child would stand in the element's own shadow root, where the page's stylesheets do not reach, and the composer refuses it at render; `check` says so first.
- A project's tokens are one file, `src/tokens.css`, the colour roles, distances, type sizes and corners every assembly's stylesheet reads as custom properties at `:root`. The build carries it whole and unscoped, named by its content, and every page links it before any assembly's sheet: `createServer` takes `styles`, the urls every page links first, and the built project declares the tokens there. A new project starts with the estate's roles, three scales and a dark scheme, each value a placeholder.
- `new` and `add agents` register the project's own MCP server for Gemini CLI (`.gemini/settings.json`) and opencode (`opencode.json`) beside Claude Code, Cursor and VS Code, and the instructions say how Codex, Zed and JetBrains AI Assistant take it.
- The build is a package of its own. `@asmjs/build` is new: what is known of a project by its directories, the modules generated for it, the bundles a project becomes and the dev loop, which were part of `@asmjs/cli`. The command line depends on it and keeps its verbs, so a project installs and runs what it did: `assemblejs build` and `assemblejs dev` are unchanged. A program that imported those names from `@asmjs/cli` imports them from `@asmjs/build`; the command line no longer exports them.
- The checks are a package of their own. `@asmjs/check` is new: the rules a project is held to, every problem found in one without building it, a project's shape, what its pages weigh, and the text of the files written for a project's agents, which were part of `@asmjs/cli`. The command line depends on it and keeps its verbs, so `assemblejs check` and `assemblejs perf` are unchanged. A program that imported those names from `@asmjs/cli` imports them from `@asmjs/check`; the command line exports its verbs and what `new` writes, and no more.
- A new project starts with `src/components.css` beside its tokens: the elements HTML already has, the button, the field with its label, the link, the list, the table, the notice and the dialog, each a class and the tokens, with its focus ring and its states and no colour of its own. The build carries it whole and unscoped after the tokens, and every page links both, in that order; the starter's one assembly is a notice with a link styled as the button. `writeProjectStyles` replaces `writeTokens`, answering both urls in order.
- `dev` records the url its server listens on under the project's root, `.assemblejs/dev.json`, for as long as that server runs. The agent surface's `render_assembly` and `compose_page` find it, ask its health, and then ask that server's content endpoint for every assembly and placement, so a framework or template view is shown as the project serves it, services and all, and nothing of the project's code runs in the tool. Without a dev server running, a plain html view is rendered as before and any other is refused with the word to start it. The command line's `Io` gains `remove`.
- `check` holds a project's tokens to their contrast in both colour schemes, as the rule `tokens-hold-their-contrast`: each ink against each ground it is set on at 4.5:1 or more, each accent against the surfaces at 3:1 or more, by WCAG 2.2's own definitions of relative luminance and contrast ratio (1.4.3 and 1.4.11, level AA). A role bound to anything but a hex colour is left alone. `readTokens`, `relativeLuminance`, `contrastRatio`, `TOKEN_INVARIANTS` and `tokenProblems` are exported.

### Patch Changes

- Updated dependencies
  - @asmjs/core@1.0.0-next.0
- What a project's author is told now holds in a project. An assembly made from a directory has one view, `default`, so the rule `a-placement-is-named-where-it-is-written` and the fix `check` gives no longer say a view may be computed, which in a project names a view the child does not have. The directive is written closed, `<assembly name="..."></assembly>`, wherever a rule, a finding or a tool's description shows it: an opening tag alone is refused where it is read. What `check` accepts and refuses of a placement is unchanged. The instructions a project is written with carry the two rules' new words, so `check` asks a project written before this to run `assemblejs add agents`.
- The instructions a project is written with say that a view writes its data escaped, and why it matters here: a value written with a raw form is markup, and an `<assembly>` directive in it is placed like one the view wrote. What `check` accepts and refuses of a project's code is unchanged. The instructions' words changed, so `check` asks a project written before this to run `assemblejs add agents`.
- Each published entry point names its own specifier in a `@module` comment, which is the name the API reference lists it under. Nothing any of them exports changes.
- The command and the library of each package are built to share one copy of the code where each carried its own. Nothing either does changes; the command line's tarball is about two thirds the size it was.
- A page, an assembly and an api file are tested against the vocabulary's own shape of a name, core's `SEGMENT`, where each carried a copy of it. A project's name has one definition, `PROJECT_NAME`, exported from the command line and asked by `new` and by `create_project`. Nothing that was accepted or refused changes.
- The agent surface lists four prompts, which a client shows its user as commands: `add_assembly`, `place_assembly`, `make_page` and `fix_findings`. Each answers a brief, one message in the person's voice, that gives the agent the order to work in, where to stop and ask, and what each tool's answer means. A prompt takes a name of the framework's own shape, or one of its renderers, and refuses anything else as invalid.
  
  `pageDocument(title, placed)` is exported from the command line: the whole document a new project's page is written with, which the prompt for a page hands over. The instructions a new project is written with say which views `render_assembly` and `compose_page` show at once and where the rest are seen.
- A framework view is read for what it places together with the components it is split into: every module it imports by a relative path, directly or through one it imports. A slot written in a component beside the view was read as nothing, so a deferred parent's child placed there arrived without its stylesheet linked ahead.
- The envelope's attributes, the attribute on its data island, the one on a deferred envelope's fallback and the two headers a content answer carries each have one definition, which the server writes from and the browser, a composing server and the command line read by: `ENVELOPE_ATTRIBUTE`, `ISLAND_ATTRIBUTE`, `FALLBACK_ATTRIBUTE` and `RESPONSE_HEADER`, exported from `@asmjs/core`, the first from `@asmjs/core/client` too. Nothing a server sends or a browser reads changes.
- A project sets how deep composition goes and how many placements one request composes in its config file: `limits: { depth, placements }` in `assemblejs.config.ts`, each a whole number, each optional, one left out keeping the default of 8 and 256. The server reads them at boot and refuses a value outside its bounds. `createServer` takes `limits` in place of `maxDepth`. `check` and the agent surface show them as they show every setting.
- `dev` and `build` are fixed for projects of any size. A build is made whole beside `dist` and replaces it only once it has succeeded, so a failed build leaves the last one as it was and the server `dev` runs loses none of its files while the next build is made; a build removes only its own files from `.assemblejs`, so `dev`'s record of its server outlives one. `dev` folds every change made during a build into one build after it, where it queued a whole build for each, and does not start a build the sources moved under. And the build no longer asks about every relative import inside a package: a project with one Svelte view built in seventeen seconds and builds in four.
- A dev server told to listen on every interface, or on one of this machine's own addresses, is still found by the agent surface. `dev` records the address it can be asked at from this machine, the loopback of the same family where it listens on every interface, and `render_assembly` and `compose_page` believe a recorded address that is a loopback name or an address of one of this machine's interfaces. Any other host in the record is another machine's and is not asked.
- The root guard follows a link's target a step at a time, as the system that opens it does. A link whose target climbed out through another link and stepped back, `out/../note.txt` with `out` a link to a directory elsewhere, was read as text, found inside the project, and the file outside was then opened by `check` and the agent surface's readers.
- A new project's guide link and its agent instructions now name the documentation of the channel it was made from: `/next/` for a prerelease and the product's own address for a stable.
  The agent instructions open with the address of `llms.txt` and `llms-full.txt`, and every package's `homepage` is `https://assemblejs.com/`.
- What the command line and the agent surface write into a file a project already has is written as that file is laid out. A placement goes on a line of its own at the indentation of what it stands beside, in the file's own line ending, and inline only where what it stands beside shares its line; into an empty body it goes one step in, as the starter writes one. Where a template writes no body, a placement at its start goes after the doctype and the head, never before them. A tag is read by its whole name and not inside another tag's attribute, so `<body-card>` and `title="<body>"` are not the body. `place_assembly` says when the template now places that assembly more than once, and refuses a template it cannot read wherever it was asked to put the placement.
  
  `add agents` writes what it adds to an `AGENTS.md`, a `CLAUDE.md` or a registration in that file's own line ending, and reads a registration through a byte order mark and writes it back behind one, where it had refused the file as not JSON.
  
  `add assembly`, and the agent surface's `add_assembly`, say what the view's renderer needs that the project has not installed, as `check` does.
- A project can be made in a directory that is already there. `assemblejs new .`, and `npm create @asmjs .`, make it in the directory the command works in, named for that directory, where each had refused the dot as a name and suggested "assembly". `new` and the agent surface's `create_project` ask one decision of what the directory may hold: what the starter does not write is left alone, a README is kept as its author wrote it, a `.gitignore` keeps every line and gains the starter's entries it lacks in its own line ending, and the files a project carries for its agents are brought up to date. Anything else the starter would write, or anything under `src`, is named and nothing is written. `create_project` sends an agent to `add_assembly` only where the root holds a `package.json`.
  
  A name with nothing usable in it is answered with an example of the thing being named, so a project, a page or an api is no longer told to call itself "assembly".
  
  Two exports change with it. `suggestName` takes that example as a second argument, which it requires. `isOccupied` is exported by `@asmjs/cli`, the one reader of whether anything is at a path, and no longer by `@asmjs/mcp`.
  
  The agent surface answers a refusal as an answer. A tool that met a path leading out of the project, a link to nothing, or a read or a write the system refused had its error carried by the protocol as a line of text; each is now `ok: false` with its problems, the path's with its rule and its fix. A dev server's record that is a link out of the project is read as no record, where it had ended `render_assembly` and `compose_page`.
- `check` reads a Pug view's elements with the attributes they were written with. Only a placement's attributes were kept, so an `img` with an alt and an `input` with an `aria-label` were each reported as having none, and an inline `style` in a Pug view was never reported. A written value is escaped as a render escapes it.
- A Svelte or a Vue view its compiler refuses is reported at the view, on the line the compiler names. The bundler had reported it where the view was imported, a line of the module the build generates, or where the error was thrown, a line of this command line's own code: `.assemblejs/client/broken.ts:10 Unexpected token` for a mistake on line 2 of `src/assemblies/broken/broken.svelte`. A Vue error no longer carries the component's absolute path in its text, since the place it is reported at names the file; and an error of no line is reported with its file alone, where it had read `file:0`.
- `dev` and `perf` take the server they started with them however they end. Stopped by a signal, the command line already stopped its server. Killed outright, it runs no line of its own, and the server was left listening on its port for as long as the machine stayed up. The server's process now ends when the command line's is gone: it is started with a channel to the process that started it and ends when that channel closes.
- A Svelte view types what it is handed. The Svelte renderer gives a view its data and its events as props, and its published `AssemblyProps` declared the data alone: a view that typed its props by it could not read `events`, and one that left them untyped, as `add assembly` wrote it, read both as `any`. `AssemblyProps` declares `events` now, and a new Svelte view is written `let { data }: AssemblyProps = $props();` with the type imported, as the scaffold already wrote every other framework's view. Nothing changes when the code runs.
- `check`, the shape and `perf` treat a page declaration they could not read as a literal, one computed whole, one with a spread among its entries, or one with no default export, as a route only a run could tell, where they said the directory's route before.
- `check` compiles a project's Svelte and Vue views with the project's own compilers, as it compiles its template views with their engines, and names a view its compiler refuses, with what the compiler said and the line. It had answered "no problems" for a view `build` then refused. The rule it is said under, `a-template-view-compiles`, is worded for every view a compiler reads; a project made before this is told by `check` that its `AGENTS.md` carries the earlier wording, and `add agents` brings it up to date.
- `check` reads what it misread, and names a file it cannot read at all. An element with a spread beside a computed attribute (`<img {...rest} src={src} />`, in JSX, Vue and Svelte) is left to the render like any element with a spread, where it was held to an `alt` or a name its spread may carry. A `Slot` in a React or Preact class component's `render` is a placement of the view's, where it was reported as standing in a Lit element's shadow root. A `Slot` or a `slot()` an author commented out in a Vue template or Svelte markup places nothing. An api file, or a view written as a module with the components it is split into, that does not compile is a finding of a new rule, `a-source-file-compiles`, with what the compiler said and the line; `check` had said no problems of a project the build then stopped on. And a placement from another server is not refused as undeclared where the config's remotes could not all be read, an origin taken from the environment being as common as one written (`declaredOrigins` answers `{ origins, whole }`).
- `check` says what it used to pass over, and `add` writes only into a project. A file that is nearly a declaration and is not read (`cart.services.ts`, `service.ts`, `home.pages.ts`, `orders.apis.ts`, a `src/apis` beside `src/api`) is a finding with the name that would be read, where it was left out of the build in silence. A README, a test or a story beside a view is no longer a second view that made its assembly no assembly; a Markdown file is a view only under its assembly's name. A link under `src` that leads nowhere is a finding of `a-project-stays-inside-its-root` (`DeadLinkError`, a refusal of the root guard's), where `check`, `build`, `dev` and `deploy` each ended in the system's own error and a stack. `add assembly` writes nothing where there is no project, so a mistyped `--cwd` makes no directory, and nothing through a link that leaves the project or leads nowhere, as the agent surface's `add_assembly` already would not. A placement naming an assembly whose directory is there and broken is told to mend the directory, not to add it.
- `compose_page` takes a page by its name and composes its template under the policy its declaration writes, as the server plans it; a placement from another server is composed deferred, so nothing is fetched. The prompts and the instructions `new` writes say so.
- `serve(project)` reads the configuration, starts the server and says where it listens. A server that refuses to start, because of a setting in the environment, a project it will not build or an address it cannot listen on, now prints its reason as plain sentences, one for each problem, and the process exits 1, where it printed a stack. A new project's server file is the import and one call.
- `perf` no longer fails a project that guards a page. It asks every page as a visitor who has not signed in, and a page that answers such a visitor 401 or 403 was counted as one that did not answer, so no project with a guarded page could pass. It is now reported as not weighed, as a page whose route has a parameter is, and the command goes on. A file an open page links that answers 401 is still a failure. And `check` and the agent surface say "an ejs assembly" and "an html assembly", where they said "a".
- `perf` weighs what a page's module scripts import before they run. It weighed the scripts a document links and nothing they import, and a build that splits its code puts most of a page's script in the chunks its one linked module imports: the frameworks example was reported at 7.9 kB of script and loads 22.5 kB before anything mounts. Each module a page links or preloads is read for what it imports and exports from, those for theirs, each file once; an import from another origin is named and not fetched, and what a module asks for later with `import()` is loaded when an assembly mounts and is not weighed. A project's `scripts` budget is held to the truer figure, so one set against the old may need raising.
- `compose_page` and `render_assembly` take what a visitor arrives with: `params`, a value for each parameter of the page's route, and `query`. Every placement's request is given them as a page's composer gives them, so a page at `/product/:sku` is shown as one product's. Until now both rendered for nobody, with no value for any parameter, and an agent was shown a page no visitor is. `compose_page` holds the values to the route the page declares: one for a parameter the route has not is refused with the ones it has, and a parameter left out is composed without and said among the problems. The three tools that show a project and change nothing are registered by `registerSeeingTools`, exported beside `registerAuthoringTools`.
  
  `@asmjs/core` exports `routeParameters`, the one reading of the names of a route's parameters. The server's route table, `perf`, which does not weigh a page whose route has one, and the agent surface each read it, where each had told a parameter by itself.
- The build's own reads, the source hash and the stylesheets and files it carries into `dist/`, go through the same root guard as every other read, so a link out of the project is refused unopened wherever the build meets it.
- The build writes the project's TypeScript setup into `.assemblejs/`, so no file of a project's needs a line saying whose JSX it is. One project for each owner of JSX the assemblies have (React's, Preact's with `jsxImportSource: "preact"`, Solid's with `jsx: "preserve"` and `"solid-js"`), decided by the build's own definition of whose a file is: an assembly's directory is its renderer's, and a `.tsx` outside every assembly that names a framework is that framework's. The sources outside the assemblies are a project every other reads, the server file, the generated modules and the config are the application's, and `.assemblejs/tsconfig.json` is the solution. The registry is written as one module per owner, `assemblies.<owner>.ts`, which `assemblies.ts` spreads in, so the render calls on a view are checked against the view's own framework and an editor shows no error in a module no hand wrote. A new project is ready to type-check by default: `typescript` and `@types/node` are development dependencies, at the versions the command line was proven with, its root `tsconfig.json` names the written setup, and `npm run typecheck` builds and runs `tsc -b`. `check` names `@types/react` and `@types/react-dom` when a project has a React view and has not installed them (`a-react-view-needs-its-types`); the build needs no types and builds without them.
- The command line's source is arranged for its split into three packages. What a view places, read from its source, is an area of its own beneath the build and no longer part of `check`, which made the build depend on the checks; the list of renderers is with what is known of a project, and the work of `add agents` with the other verbs. Every name the package exports is exported as before, and nothing it does changes.
- The command line reads its arguments, and a new project starts as a page. `--version` and `-v` say the version, where each was an unknown command. A flag is read written apart or with an equals, `--cwd=shop`; a flag nobody knows, or one left without its value, is refused with the usage, where it was kept in silence with the word after it. `new` writes into an absolute directory where it says. `add assembly` with no name says a name is needed. A new project's tokens declare both colour schemes and its components style the page itself, its ground, its ink and its type, so its first page is no longer black Times on white beneath dark tokens. A project made by pnpm carries pnpm's ruling on esbuild's install script, without which pnpm 11 fails its first install.
- The agent surface answers `assemblejs://contract`: the three endpoints, their headers with their shapes, the manifest's fields and the envelope, every name the one the server writes, for an agent implementing an assembly on another server. The instructions `new` writes name it.
